# 九重天堂 — 项目架构设计

> Godot 4 GDScript | DND×明日方舟 世界观 | 网格自走棋肉鸽 RPG MVP

---

## 一、项目概述

### 1.1 核心玩法

玩家以上帝视角，将角色卡牌部署到网格场地进行实时自走棋战斗。角色自动索敌攻击，玩家可手动施放技能、切换姿态、撤退回收。PVE 肉鸽模式中玩家逐层推进，在酒馆招募队友，最终挑战 Boss。

### 1.2 技术选型

| 项目 | 选型 |
|------|------|
| 引擎 | Godot 4 |
| 语言 | GDScript |
| 架构 | 场景树 + 信号驱动 + 组合模式 |

### 3.1 节点间通信（信号流）

```
RoguelikeManager  → recruit_phase_started  → RecruitUI (显示招募)
                  → battle_phase_started   → (内部衔接)

DeploymentSystem  → hand_updated          → DeploymentBar (刷新手牌)
                  → unit_selected         → SkillPanel (显示面板)
                  → unit_deselected       → SkillPanel (隐藏面板)
                  → unit_selected         → DeploymentBar (刷新)

GridSystem        → cell_clicked          → DeploymentSystem (点击部署/选中)

ResourceManager   → dp_changed            → ResourceBar (更新 DP 条)
                                          → DeploymentBar (更新按钮状态)

BattleManager     → battle_won / battle_lost → RoguelikeManager (战斗结算)
```

## 四、核心系统

### 4.1 战斗状态机（BattleManager）

```
                  ┌─────────────────────────────────────┐
                  │                                     │
                  ▼                                     │
          ┌──────────────┐   按F    ┌──────────────┐    │
  启动 ──▶│  PREPARING   │────────▶│ IN_PROGRESS  │    │
          │  (准备阶段)   │         │  (战斗中)     │    │
          └──────────────┘         └──────┬───────┘    │
                                          │ 波次清空    │
                                          ▼             │
                                   ┌──────────────┐    │
                                   │ WAVE_BREAK   │────┘ (下一波)
                                   │  (波次间隙)   │
                                   └──────┬───────┘
                                          │ 全部波次完成
                                          ▼
                                   ┌──────────────┐
                                   │   VICTORY    │
                                   └──────────────┘
```

| 状态 | 部署 | AI | DP 增长 | 说明 |
|------|------|-----|---------|------|
| PREPARING | ✅ 静态部署 | ❌ 静止 | ❌ | 布阵阶段 |
| IN_PROGRESS | ✅ 实时部署 | ✅ 激活 | ✅ | 战斗中 |
| WAVE_BREAK | ✅ 实时部署 | ✅ 激活 | ✅ | 波次间隙可补人 |
| VICTORY | ❌ | - | - | 战斗胜利，结算 |
| DEFEAT | ❌ | - | - | 战斗失败 |

### 4.2 部署模式

**两种部署模式共存，由 BattleManager 状态自动切换：**

1. **静态部署（PREPARING 阶段）**
   - 部署后角色 `ai_enabled = false`，静止在格子上
   - DP 固定（不自然恢复），消耗初始分配量
   - 布阵完成后按 `F` 推进 → `start_next_wave()` 激活全场 AI

2. **实时部署（IN_PROGRESS / WAVE_BREAK 阶段）**
   - 部署后角色 `ai_enabled = true`，立即索敌移动攻击
   - DP 每秒自然恢复 1 点
   - 手牌栏始终可用，DP 够即可随时增援

```
HeroUnit.setup()
  └─ match BattleManager.state:
       PREPARING → deactivate_ai()     # 静止
       _         → activate_ai()       # 立即行动

BattleManager.start_next_wave()
  └─ for player_units: activate_ai()   # 全场激活
```

### 4.3 网格系统（GridSystem）

- **尺寸**：20 列 × 12 行，每格 64px
- **部署区**：第 0-4 行（玩家可部署的半场，绿色标记）
- **敌方出生点**：右侧边缘（第 19 列对应的行）
- **占据表**：`Dictionary[Vector2i, Node]`，O(1) 查找
- **路径计算**：BFS 寻路（4 方向，避开占据格）
- **可视化**：`_draw()` 绘制网格线 + 区域高亮

核心 API：
```
grid_to_world(grid_pos) → Vector2       # 网格 → 世界坐标
world_to_grid(world_pos) → Vector2i      # 世界 → 网格坐标
can_place_at(grid_pos) → bool            # 是否可部署
place_unit(unit, grid_pos) → bool        # 放置单位
get_units_in_range(center, radius, team) # 范围查询
get_nearest_unit(center, team)           # 最近单位
find_path(from, to) → Array              # BFS 寻路
```

### 4.4 资源系统（ResourceManager）

```
DP（Deployment Points）：部署角色 / 施放技能的消耗资源

- 最大值：100
- 初始值：20（每次战斗开始时）
- 恢复速率：1 点/秒（PREPARING 阶段暂停）
- 消耗：职业部署费用（7-15 DP）+ 技能 DP 费用（3-15 DP）
- 返还：撤退返还 50% 部署费用
```

## 五、单位系统

### 5.1 类继承

```
Node2D
  └── UnitBase                    # 属性、血条、AI、技能
        ├── HeroUnit              # + 选中、撤退、快捷键(QWER/空格/R)
        └── EnemyUnit             # + 敌人模板、颜色区分
```

### 5.2 UnitBase 核心属性

| 分类 | 属性 | 说明 |
|------|------|------|
| 网格 | `grid_position` | 当前所在格子 |
| 战斗 | `max_hp` `current_hp` `attack` `defense` | 基础数值 |
| 速度 | `attack_speed` `move_speed` | 攻速（次/秒）、移速（格/秒） |
| 范围 | `attack_range` `search_range` | 攻击范围、索敌范围 |
| 姿态 | `stance` | MARCH（行进）/ STATIONED（驻扎） |
| AI | `ai_controller` `ai_enabled` | AI 实例 + 启停标志 |
| 冷却 | `attack_cooldown` `skill_cooldowns` | 攻击 & 技能冷却计时 |

### 5.3 UnitAI 状态机

```
                无目标 + 可移动
    ┌──────┐ ────────────────▶ ┌────────┐
    │ idle │                    │ moving │
    └──┬───┘ ◀──────────────── │        │──┐
       │     到达 / 无路径       └───┬────┘  │
       │ 发现目标                   │发现目标│
       ▼ 在攻击范围内               │        │
    ┌──────────┐                   │        │
    │attacking │◀──────────────────┘        │
    └────┬─────┘                             │
         │ 目标死亡/超出攻击范围              │
         └──────────────────────────────────┘
```

索敌逻辑按职业模板的 `target_priority` 筛选：
- `NEAREST` — 最近
- `LOWEST_HP` — 最低血量
- `HIGHEST_ATK` — 最高攻击力
- `FARTHEST` — 最远

### 5.4 姿态系统

| 姿态 | 移动 | 防御 | 攻击力 | 范围 | 特性 |
|------|------|------|--------|------|------|
| 行进 (MARCH) | ✅ 高速 | 基础 | ×0.5-0.9 | 基础 | 默认姿态 |
| 驻扎 (STATIONED) | ❌ 定身 | ×1.2-2.0 | 基础 | ×1.5-2.0 | 按空格切换 |

### 5.5 血条

每个单位实体上方显示血条：
- **背景**：深灰半透明
- **填充**：玩家蓝色 `(0.25, 0.6, 1.0)` / 敌人红色 `(1.0, 0.2, 0.2)`
- 通过 `hp_changed` 信号驱动，`_update_hp_bar()` 方法更新宽度

### 8.1 流程生命周期

```
start_run()
  └─ 初始队伍 [战士, 游侠]，金币 100，楼层 1
       │
       ▼
  ┌──────────┐  购买/跳过   ┌──────────┐
  │  招募阶段  │──────────▶│  地图推进  │
  │ RECRUIT   │            │   MAP     │
  └──────────┘            └────┬─────┘
       ▲                       │ 选择节点
       │                       ▼
       │               ┌──────────────┐
       │               │   战斗阶段     │
       ├───────────────│   BATTLE      │
       │   胜利         └──────────────┘
       │   (+金币)            │

       │               ┌──────────────┐
```

## 九、完整战斗时序

```
┌─────────────────────────────────────────────────────────────────┐
│ 1. 启动                                                         │
│    Startup._ready → RoguelikeManager.start_run()                │
│    → GameManager: 初始队伍 [战士,游侠], 金币100                   │
│    → 进入招募阶段                                                 │
├─────────────────────────────────────────────────────────────────┤
│ 2. 招募                                                         │
│    RecruitUI 显示 4 个选项 → 购买/跳过                            │
│    → RoguelikeManager.skip_recruit()                             │
│    → _enter_map_phase → _advance_to_next_node                   │
├─────────────────────────────────────────────────────────────────┤
│ 3. 战斗准备 (_start_battle)                                      │
│    → DeploymentSystem.setup_hand(party)  # 手牌初始化            │
│    → BattleManager.setup_battle()         # state = PREPARING   │
│    → ResourceManager.reset_dp(20, 100)    # 初始 DP             │
│    → 等待玩家操作                                                │
├─────────────────────────────────────────────────────────────────┤
│ 4. 玩家部署 (PREPARING 状态)                                     │
│    点击手牌 → 拖拽 → 点击网格 → deploy_card()                     │
│    HeroUnit.setup() → ai_enabled = false (静止)                 │
│    重复直到部署完毕 / DP 耗尽                                     │
├─────────────────────────────────────────────────────────────────┤
│ 5. 波次开始 (按 F → start_next_wave)                             │
│    → state = IN_PROGRESS                                        │
│    → 激活全场玩家 AI (activate_ai)                                │
│    → 生成敌方波次                                                 │
├─────────────────────────────────────────────────────────────────┤
│ 6. 战斗中 (IN_PROGRESS)                                         │
│    每个单位 UnitAI 每帧:                                         │
│      idle → 索敌 → moving/attacking                             │
│    DP 自然恢复 → 可实时部署增援（ai_enabled=true）                │
│    玩家可选中单位 → 按 Q/W/E 施放技能 / 空格切换姿态 / R 撤退     │
├─────────────────────────────────────────────────────────────────┤
│ 7. 波次间隙 (WAVE_BREAK)                                        │
│    所有敌人被消灭 → check_battle_end() → wave_cleared            │
│    可按 F 推进下一波，或部署增援                                   │
├─────────────────────────────────────────────────────────────────┤
│ 8. 战斗结算                                                     │
│    全部波次完成 → VICTORY → 奖励金币 → 进入招募阶段               │
│    所有玩家单位死亡 → DEFEAT → 肉鸽结束                          │
└─────────────────────────────────────────────────────────────────┘
```

## 十一、设计原则

1. **信号驱动**：系统间通过 Godot 信号解耦，避免硬引用
2. **组合优于继承**：UnitAI、ClassTemplate 作为组件组合到 UnitBase
3. **状态机优先**：BattleManager 状态决定所有子系统的行为分支
4. **单场景 MVP**：整个游戏在 `main.tscn` 中运行，通过 CanvasLayer 切换 UI
5. **静态工厂**：职业模板通过 `ClassDefinitions.get_template()` 缓存创建
