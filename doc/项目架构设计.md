# 九重天堂 — 项目架构设计

> Godot 4 GDScript | DND×明日方舟 世界观 | 网格自走棋肉鸽 RPG MVP

---

## 一、项目概述

### 1.1 核心玩法

玩家以上帝视角，将角色卡牌部署到网格场地进行实时自走棋战斗。角色自动索敌攻击，玩家可手动施放技能、切换姿态、撤退回收。PVE 肉鸽模式中玩家逐层推进，在酒馆招募队友，最终挑战 Boss。

局外养成由冒险小队、AFK 放置爬塔和装备系统承载。AFK 模式与自走棋战斗完全隔离，玩家配置冒险小队进行爬塔，系统按小队整体攻击力运行轻量自动战斗，再播放战斗表现并结算奖励。装备系统作为长期养成和金币回收入口，每件装备最多持有 1 个特殊词条，词条用于轻量改变英雄机制或流派倾向，但游戏构筑重心仍保持在羁绊组合上。

### 1.2 技术选型

| 项目 | 选型 |
|------|------|
| 引擎 | Godot 4 |
| 语言 | GDScript |
| 架构 | 场景树 + 信号驱动 + 组合模式 |

## 三、场景结构

### 3.1 启动与入口流

```
启动游戏
  └─ StartMenu
       ├─ 选择 / 创建 / 加载存档
       ├─ 游戏设置
       └─ 退出游戏
            │
            ▼
       AfkHub
       ├─ AFK 爬塔主界面
       ├─ 英雄养成入口
       ├─ 装备背包入口
       ├─ 图鉴入口
       └─ 肉鸽模式入口
```

主菜单只负责存档选择、存档创建、设置和退出。玩家进入某个存档后，默认来到 AFK 模式主界面；所有局外养成和进入肉鸽模式的入口都放在 AFK 界面中。

### 3.2 主菜单场景

```
StartMenu (Control)
├── 存档槽位列表
│   ├── 继续当前存档
│   ├── 创建新存档
│   └── 切换存档
├── 游戏设置
└── 退出游戏
```

StartMenu 不直接打开英雄养成、装备、图鉴或肉鸽模式；选定存档后通过 `change_scene_to_file("res://scenes/afk_hub.tscn")` 进入 AFK Hub。

### 3.3 AFK 模式主界面

```
AfkHub (Control)
├── AfkTowerUI                      # 默认主面板：爬塔进度、小队战力、挂机收益
├── 顶部资源栏                       # 存档金币、材料、当前存档信息
├── 功能入口
│   ├── 英雄养成                    # 打开 CharacterStorageUI
│   ├── 装备背包                    # 打开 EquipmentUI
│   ├── 图鉴                        # 进入 encyclopedia.tscn
│   └── 肉鸽模式                    # 支付入场费后进入 main.tscn
└── 覆盖层 UI
    ├── CharacterStorageUI
    └── EquipmentUI
```

AFK Hub 是进入存档后的局外大厅。它负责展示挂机收益、爬塔进度和冒险小队总战力，并承载英雄养成、装备背包、图鉴和肉鸽模式入口。

### 3.4 自走棋肉鸽主场景

```
Main (Node2D)
├── GridSystem (Node2D)              # 20×12 网格，可视化绘制，点击检测
├── DeploymentSystem (Node)          # 手牌管理 + 拖拽部署 + 选中控制
├── RoguelikeManager (Node)          # 肉鸽生命周期
│   └── RecruitSystem (Node)         # 招募子节点
├── Startup (Node)                   # 启动引导 + 快捷键（F/ESC）
└── UICanvas (CanvasLayer)
    ├── ResourceBar (Control)        # DP 条 + 金币 + 波次信息
    ├── DeploymentBar (Control)      # 底部手牌卡牌按钮
    ├── SkillPanel (Control)         # 选中单位技能/操作面板
    └── RecruitUI (Control)          # 全屏酒馆招募界面
```

### 3.5 节点间通信（信号流）

```
RoguelikeManager  → recruit_phase_started  → RecruitUI (显示招募)
                  → battle_phase_started   → (内部衔接)

DeploymentSystem  → hand_updated          → DeploymentBar (刷新手牌)
                  → unit_selected         → SkillPanel (显示面板)
                  → unit_deselected       → SkillPanel (隐藏面板)
                  → unit_selected         → DeploymentBar (刷新)

GridSystem        → cell_clicked          → DeploymentSystem (点击部署/选中)

ResourceManager   → dp_changed            → ResourceBar (更新 DP 条)
                                          → DeploymentBar (更新按钮状态)

BattleManager     → battle_won / battle_lost → RoguelikeManager (战斗结算)

AfkHubUI          → open_character_storage  → CharacterStorageUI
                  → open_equipment_bag      → EquipmentUI
                  → open_encyclopedia       → encyclopedia.tscn
                  → start_roguelike         → main.tscn

AfkTowerManager   → afk_team_changed      → AfkTowerUI (刷新小队与战力)
                  → afk_rewards_claimed   → AfkTowerUI / ResourceDisplay

EquipmentManager  → equipment_changed     → CharacterStorageUI / EquipmentUI
                  → affix_rerolled        → EquipmentUI (刷新词条)
```

## 四、核心系统

### 4.1 战斗状态机（BattleManager）

```
                  ┌─────────────────────────────────────┐
                  │                                     │
                  ▼                                     │
          ┌──────────────┐   按F    ┌──────────────┐    │
  启动 ──▶│  PREPARING   │────────▶│ IN_PROGRESS  │    │
          │  (准备阶段)   │         │  (战斗中)     │    │
          └──────────────┘         └──────┬───────┘    │
                                          │ 波次清空    │
                                          ▼             │
                                   ┌──────────────┐    │
                                   │ WAVE_BREAK   │────┘ (下一波)
                                   │  (波次间隙)   │
                                   └──────┬───────┘
                                          │ 全部波次完成
                                          ▼
                                   ┌──────────────┐
                                   │   VICTORY    │
                                   └──────────────┘
```

| 状态 | 部署 | AI | DP 增长 | 说明 |
|------|------|-----|---------|------|
| PREPARING | ✅ 静态部署 | ❌ 静止 | ❌ | 布阵阶段 |
| IN_PROGRESS | ✅ 实时部署 | ✅ 激活 | ✅ | 战斗中 |
| WAVE_BREAK | ✅ 实时部署 | ✅ 激活 | ✅ | 波次间隙可补人 |
| VICTORY | ❌ | - | - | 战斗胜利，结算 |
| DEFEAT | ❌ | - | - | 战斗失败 |

### 4.2 部署模式

**两种部署模式共存，由 BattleManager 状态自动切换：**

1. **静态部署（PREPARING 阶段）**
   - 部署后角色 `ai_enabled = false`，静止在格子上
   - DP 固定（不自然恢复），消耗初始分配量
   - 布阵完成后按 `F` 推进 → `start_next_wave()` 激活全场 AI

2. **实时部署（IN_PROGRESS / WAVE_BREAK 阶段）**
   - 部署后角色 `ai_enabled = true`，立即索敌移动攻击
   - DP 每秒自然恢复 1 点
   - 手牌栏始终可用，DP 够即可随时增援

```
HeroUnit.setup()
  └─ match BattleManager.state:
       PREPARING → deactivate_ai()     # 静止
       _         → activate_ai()       # 立即行动

BattleManager.start_next_wave()
  └─ for player_units: activate_ai()   # 全场激活
```

### 4.3 网格系统（GridSystem）

- **尺寸**：20 列 × 12 行，每格 64px
- **部署区**：第 0-4 行（玩家可部署的半场，绿色标记）
- **敌方出生点**：右侧边缘（第 19 列对应的行）
- **占据表**：`Dictionary[Vector2i, Node]`，O(1) 查找
- **路径计算**：BFS 寻路（4 方向，避开占据格）
- **可视化**：`_draw()` 绘制网格线 + 区域高亮

核心 API：
```
grid_to_world(grid_pos) → Vector2       # 网格 → 世界坐标
world_to_grid(world_pos) → Vector2i      # 世界 → 网格坐标
can_place_at(grid_pos) → bool            # 是否可部署
place_unit(unit, grid_pos) → bool        # 放置单位
get_units_in_range(center, radius, team) # 范围查询
get_nearest_unit(center, team)           # 最近单位
find_path(from, to) → Array              # BFS 寻路
```

### 4.4 资源系统（ResourceManager）

```
DP（Deployment Points）：部署角色 / 施放技能的消耗资源

- 最大值：100
- 初始值：20（每次战斗开始时）
- 恢复速率：1 点/秒（PREPARING 阶段暂停）
- 消耗：职业部署费用（7-15 DP）+ 技能 DP 费用（3-15 DP）
- 返还：撤退返还 50% 部署费用
```

## 五、单位系统

### 5.1 类继承

```
Node2D
  └── UnitBase                    # 属性、血条、AI、技能
        ├── HeroUnit              # + 选中、撤退、快捷键(QWER/空格/R)
        └── EnemyUnit             # + 敌人模板、颜色区分
```

### 5.2 UnitBase 核心属性

| 分类 | 属性 | 说明 |
|------|------|------|
| 网格 | `grid_position` | 当前所在格子 |
| 战斗 | `max_hp` `current_hp` `attack` `defense` | 基础数值 |
| 速度 | `attack_speed` `move_speed` | 攻速（次/秒）、移速（格/秒） |
| 范围 | `attack_range` `search_range` | 攻击范围、索敌范围 |
| 姿态 | `stance` | MARCH（行进）/ STATIONED（驻扎） |
| AI | `ai_controller` `ai_enabled` | AI 实例 + 启停标志 |
| 冷却 | `attack_cooldown` `skill_cooldowns` | 攻击 & 技能冷却计时 |

### 5.3 UnitAI 状态机

```
                无目标 + 可移动
    ┌──────┐ ────────────────▶ ┌────────┐
    │ idle │                    │ moving │
    └──┬───┘ ◀──────────────── │        │──┐
       │     到达 / 无路径       └───┬────┘  │
       │ 发现目标                   │发现目标│
       ▼ 在攻击范围内               │        │
    ┌──────────┐                   │        │
    │attacking │◀──────────────────┘        │
    └────┬─────┘                             │
         │ 目标死亡/超出攻击范围              │
         └──────────────────────────────────┘
```

索敌逻辑按职业模板的 `target_priority` 筛选：
- `NEAREST` — 最近
- `LOWEST_HP` — 最低血量
- `HIGHEST_ATK` — 最高攻击力
- `FARTHEST` — 最远

### 5.4 姿态系统

| 姿态 | 移动 | 防御 | 攻击力 | 范围 | 特性 |
|------|------|------|--------|------|------|
| 行进 (MARCH) | ✅ 高速 | 基础 | ×0.5-0.9 | 基础 | 默认姿态 |
| 驻扎 (STATIONED) | ❌ 定身 | ×1.2-2.0 | 基础 | ×1.5-2.0 | 按空格切换 |

### 5.5 血条

每个单位实体上方显示血条：
- **背景**：深灰半透明
- **填充**：玩家蓝色 `(0.25, 0.6, 1.0)` / 敌人红色 `(1.0, 0.2, 0.2)`
- 通过 `hp_changed` 信号驱动，`_update_hp_bar()` 方法更新宽度

## 八、肉鸽系统

### 8.1 流程生命周期

```
start_run()
  └─ 初始队伍 [战士, 游侠]，金币 100，楼层 1
       │
       ▼
  ┌──────────┐  购买/跳过   ┌──────────┐
  │  招募阶段  │──────────▶│  地图推进  │
  │ RECRUIT   │            │   MAP     │
  └──────────┘            └────┬─────┘
       ▲                       │ 选择节点
       │                       ▼
       │               ┌──────────────┐
       │               │   战斗阶段     │
       ├───────────────│   BATTLE      │
       │   胜利         └──────────────┘
       │   (+金币)            │
       │                      │ 失败
       │                      ▼
       │               ┌──────────────┐
       │               │   ENDED      │
       │               └──────────────┘
       │
       └── 楼层 1: battle → battle → shop → boss
           楼层 2: battle → elite → battle → shop → boss
           楼层 3: elite → battle → shop → elite → boss
```

### 8.2 招募系统

- 每次 4 个随机选项，30% 概率出现高等级（Lv.2+）角色
- 基础费用 20 金币，稀有角色 ×1.5 × level
- 可通过消耗金币购买，也可跳过

### 8.3 敌人系统

6 种敌人模板 + 楼层缩放：

| 敌人 | 类型 | HP | ATK | 特性 |
|------|------|----|------|------|
| 哥布林 | 近战 | 60 | 8 | 快速小型 |
| 骷髅兵 | 近战 | 80 | 12 | 标准中型 |
| 骷髅弓手 | 远程 | 50 | 15 | 远程打击 |
| 食人魔 | 重装 | 200 | 25 | 大型肉盾 |
| 石像鬼 | 远程 | 70 | 18 | 高速飞行 |
| 巨龙 | Boss | 500 | 40 | 最终 Boss |

楼层强化系数：普通 ×(1.0 + (楼层-1)×0.3)，精英 ×1.5，Boss ×(1.0 + (楼层-1)×0.5)

### 8.4 肉鸽难度与入场费

肉鸽模式作为局内高价值玩法，需要消耗存档金币进入。入场费用于回收 AFK 放置产出的溢出金币，并让高难挑战形成“风险投资”循环。

| 难度 | 入场费定位 | 结局奖励定位 | 设计目的 |
|------|------------|--------------|----------|
| 普通 | 低 | 入场费数倍金币 + 基础装备 | 新手循环、稳定养成 |
| 困难 | 中 | 更高金币倍率 + 稀有装备/材料 | 中期金币回收和构筑验证 |
| 噩梦 | 高 | 高倍率金币 + 稀有重铸材料 | 长期消耗金币，追求词条 |
| 深渊 | 极高 | 专属材料/词条权重，金币不是唯一重点 | 终局挑战和稀缺资源来源 |

规则建议：
- 入场费消耗的是存档金币，局内酒馆仍使用单局金币 `run_gold`。
- 进入肉鸽时立即扣除入场费。
- 第一场战斗开始前放弃可返还少量金币，开始战斗后放弃不返还。
- 高难允许玩家刷开局祝福、初始酒馆或初始队伍，每次刷新消耗金币，且同一局刷新次数越多费用越高。
- 困难以上结算应稳定产出装备或重铸材料，避免终局奖励只扩大金币通胀。

## 九、局外 AFK 爬塔与装备系统

AFK 模式是局外养成玩法，不复用自走棋战斗模拟。它只读取角色、职业、羁绊和装备数据，计算冒险小队整体攻击力，再由轻量自动战斗逻辑推进敌人血量、敌人动作和塔层进度。战斗表现由 UI 动画播放，不实例化 `HeroUnit`、`EnemyUnit`，也不进入 `BattleManager`。

### 9.1 模式边界

AFK 爬塔复用：
- `GameManager.owned_characters`：持有角色、等级、养成进度
- `ClassDefinitions`：职业基础属性和职业标签
- `SynergyManager` / `synergies.json`：小队羁绊识别和战力加成
- `EquipmentManager`：角色装备和特殊词条
- `GameManager.save_game()`：金币、装备、塔层进度保存

AFK 爬塔不复用：
- `BattleManager`
- `GridSystem`
- `DeploymentSystem`
- `ResourceManager` 的 DP 逻辑
- `UnitAI`
- `HeroUnit` / `EnemyUnit` 实体战斗

### 9.2 AFK 爬塔流程

```
进入存档并打开 AFK Hub
  └─ 读取存档角色 / 装备 / 塔层进度
       │
       ▼
领取挂机收益 / 查看塔层进度
       │
       ▼
配置冒险小队
  └─ 选择 1-5 名角色，展示羁绊和总战力
       │
       ▼
挑战当前塔层
  └─ CombatPowerCalculator 计算 team_attack
  └─ AfkTowerManager 运行英雄/敌人交替动作
       │
       ├─ 英雄动作：按小队攻击力扣除敌人血量
       ├─ 敌人动作：只播放表现，不造成伤害
       ├─ 点击鼓舞：短时间提高 50% 英雄攻击频率
       └─ 击败敌人：自动进入下一名敌人 / 下一层
```

AFK 战斗只有小队攻击力、敌人血量、动作计时和层数进度，不设置英雄血量，也不创建真实战斗场景。UI 只订阅 `AfkTowerManager` 的状态快照并播放小队头像、敌人受击、技能闪光、奖励飞入资源栏等轻量表现。

### 9.3 战力计算

AFK 战力应突出羁绊构筑，而不是单纯堆装备。

```
角色战力 =
  基础生命 × hp_weight
+ 基础攻击 × atk_weight
+ 基础防御 × def_weight
+ 攻速/技能系数
+ 等级修正
+ 装备基础属性
+ 单个特殊词条修正

小队总战力 =
  所有角色战力之和
× 羁绊战力倍率
× 塔玩法专属修正
```

设计约束：
- 羁绊倍率应是小队总战力的重要来源，鼓励玩家围绕职业/国家/信仰组合配置队伍。
- 装备提供角色个体强化和流派微调，不应压过羁绊构筑。
- 特殊词条以改变攻击、治疗、技能或姿态表现为主，避免堆叠多个词条导致构筑不可读。
- AFK 判定优先采用确定性结果，玩家应能看到“当前战力 / 推荐战力 / 差距”。

### 9.4 AFK 奖励

AFK 奖励负责提供长期基础积累，但关键稀有资源仍应由肉鸽结算提供。

| 来源 | 奖励 | 定位 |
|------|------|------|
| 挂机收益 | 金币、少量经验、低概率装备 | 日常积累 |
| 爬塔首通 | 金币、装备、功能解锁 | 推进目标 |
| 爬塔重复 | 金币、低阶装备、少量材料 | 稳定回收 |
| 高层爬塔 | 较高装备掉率、少量重铸材料 | 局外挑战 |

离线收益需要设置上限，例如 8-12 小时，避免长时间离线造成经济爆炸。

### 9.5 装备系统

装备是金币长期消耗和流派微调系统。每个角色按职业类型穿戴对应武器，装备来源包括肉鸽稳定获取和 AFK 概率掉落。

装备数据建议：
```
{
  "equipment_id": "sword_001",
  "class_type": "warrior",
  "level": 1,
  "base_stats": {
    "attack": 12,
    "defense": 4
  },
  "special_affix": "chain_reaction",
  "affix_tier": 2,
  "owner_class_id": "warrior"
}
```

装备限制：
- 每件装备最多 1 个特殊词条。
- 词条不做多词条组合，避免装备系统喧宾夺主。
- 词条效果应服务于职业特色和羁绊构筑，例如让单体攻击附带连锁、让治疗溢出转化护盾、让驻扎姿态获得额外收益。
- 同类机制词条需要限制触发频率或叠加规则，避免单个词条破坏自走棋战斗平衡。

### 9.6 重铸消耗

特殊词条可通过重铸替换，是金币和稀有材料的核心消耗口。

| 操作 | 消耗 | 说明 |
|------|------|------|
| 普通重铸 | 大量金币 + 普通重铸材料 | 随机生成同职业词条 |
| 定向重铸 | 大量金币 + 肉鸽稀有结算材料 | 限定词条池或词条类型 |
| 高阶重铸 | 巨量金币 + 高难肉鸽材料 | 追求高阶机制词条 |

经济闭环：
```
AFK 爬塔 → 稳定产金币，概率掉装备
肉鸽入场 → 消耗金币，产出装备和稀有重铸材料
装备重铸 → 消耗大量金币和稀有材料，强化构筑
强化后的队伍 → 推进更高难肉鸽和 AFK 塔层
```

```
┌─────────────────────────────────────────────────────────────────┐
│ 1. 启动                                                         │
│    Startup._ready → RoguelikeManager.start_run()                │
│    → GameManager: 初始队伍 [战士,游侠], 金币100                   │
│    → 进入招募阶段                                                 │
├─────────────────────────────────────────────────────────────────┤
│ 2. 招募                                                         │
│    RecruitUI 显示 4 个选项 → 购买/跳过                            │
│    → RoguelikeManager.skip_recruit()                             │
│    → _enter_map_phase → _advance_to_next_node                   │
├─────────────────────────────────────────────────────────────────┤
│ 3. 战斗准备 (_start_battle)                                      │
│    → DeploymentSystem.setup_hand(party)  # 手牌初始化            │
│    → BattleManager.setup_battle()         # state = PREPARING   │
│    → ResourceManager.reset_dp(20, 100)    # 初始 DP             │
│    → 等待玩家操作                                                │
├─────────────────────────────────────────────────────────────────┤
│ 4. 玩家部署 (PREPARING 状态)                                     │
│    点击手牌 → 拖拽 → 点击网格 → deploy_card()                     │
│    HeroUnit.setup() → ai_enabled = false (静止)                 │
│    重复直到部署完毕 / DP 耗尽                                     │
├─────────────────────────────────────────────────────────────────┤
│ 5. 波次开始 (按 F → start_next_wave)                             │
│    → state = IN_PROGRESS                                        │
│    → 激活全场玩家 AI (activate_ai)                                │
│    → 生成敌方波次                                                 │
├─────────────────────────────────────────────────────────────────┤
│ 6. 战斗中 (IN_PROGRESS)                                         │
│    每个单位 UnitAI 每帧:                                         │
│      idle → 索敌 → moving/attacking                             │
│    DP 自然恢复 → 可实时部署增援（ai_enabled=true）                │
│    玩家可选中单位 → 按 Q/W/E 施放技能 / 空格切换姿态 / R 撤退     │
├─────────────────────────────────────────────────────────────────┤
│ 7. 波次间隙 (WAVE_BREAK)                                        │
│    所有敌人被消灭 → check_battle_end() → wave_cleared            │
│    可按 F 推进下一波，或部署增援                                   │
├─────────────────────────────────────────────────────────────────┤
│ 8. 战斗结算                                                     │
│    全部波次完成 → VICTORY → 奖励金币 → 进入招募阶段               │
│    所有玩家单位死亡 → DEFEAT → 肉鸽结束                          │
└─────────────────────────────────────────────────────────────────┘
```

## 十二、设计原则

1. **信号驱动**：系统间通过 Godot 信号解耦，避免硬引用
2. **组合优于继承**：UnitAI、ClassTemplate 作为组件组合到 UnitBase
3. **状态机优先**：BattleManager 状态决定所有子系统的行为分支
4. **场景职责清晰**：`start_menu.tscn` 只负责存档和设置，`afk_hub.tscn` 是进入存档后的局外大厅，`main.tscn` 承载自走棋肉鸽战斗
5. **静态工厂**：职业模板通过 `ClassDefinitions.get_template()` 缓存创建
6. **模式隔离**：自走棋肉鸽使用真实单位和战斗状态机，AFK 爬塔只做轻量自动战斗、战力计算和 UI 表现
7. **羁绊优先**：装备和词条用于辅助流派，不取代羁绊作为主要构筑来源
8. **金币闭环**：AFK 产出金币，肉鸽入场费和装备重铸回收金币，稀有材料限制终局膨胀
