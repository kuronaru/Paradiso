# 九重天堂 — 英雄角色设计方案

> 适用范围：PVE 肉鸽自走棋模式  
> 设计目标：基于《羁绊机制设计方案》中的职业主羁绊、六维小羁绊与阵营小羁绊，先为每个 DND 职业小分支建立一名“平凡基础角色”和一个“基础技能”。后续更有记忆点的英雄、稀有角色、多职业角色都从这些基础模板延申。

---

## 一、设计口径

1. **基础角色不是最终英雄上限**  
   本文中的角色都是普通模板：没有专属剧情、没有独特机制、没有强个人被动。它们用于验证职业池、酒馆刷新、羁绊计数和基础战斗定位。

2. **按羁绊类型分类，而不是按故事阵营分类**  
   角色首先归入职业主羁绊，其次提供六维属性小羁绊与阵营小羁绊。一个角色默认贡献：

```text
1 个职业主羁绊
1~2 个六维小羁绊
1~2 个阵营小羁绊
```

3. **每个职业小分支先提供一名基础角色**  
   当前职业池包含 13 个职业大分支，每个职业先采用 3 个小分支示例，因此基础角色池共 39 名。这个数量足够支撑 `6 人主羁绊 + 3 人小羁绊` 的构筑验证。

4. **基础技能必须稳定、短句、可调数值**  
   基础技能优先使用攻击、施法、周期、受击、治疗等稳定触发；不把击杀、暴击、低血、濒死作为核心触发。技能描述只定义战斗意图，具体倍率、冷却、范围和成长由后续数值表配置。

5. **小分支塑造单卡，不额外成为羁绊**  
   小分支用于决定角色的攻击方式、技能形态和职业内定位。小分支名称可以被遗物、事件或高稀有角色引用，但 MVP 不把小分支做成独立羁绊。

## 二、字段模板

建议后续数据化时，每名基础角色至少拥有以下字段：

```text
CharacterDraft
├── character_id
├── display_name
├── class_group          # 职业主羁绊
├── subclass_id          # 职业小分支
├── stat_tags            # 六维小羁绊
├── alignment_tags       # 阵营小羁绊
├── combat_role          # 队内定位
├── basic_skill_name
└── basic_skill_desc
```

本文先使用中文草案名；落地到 Godot 数据时可统一转为 snake_case id。

## 六、MVP 优先落地角色

当前 Godot 工程已有五个职业模板映射：战士、游侠、法师、牧师、游荡者。MVP 可先落地以下 15 名基础角色，快速覆盖现有战斗模板与羁绊 UI：

| 职业 | 优先角色 |
| --- | --- |
| 战士 Fighter | 冠军剑士、战斗教官、奥法骑士 |
| 游侠 Ranger | 猎人斥候、兽王训导、幽域追踪者 |
| 法师 Wizard | 塑能法师、防护法师、预言法师 |
| 牧师 Cleric | 生命助祭、光明助祭、战争助祭 |
| 游荡者 Rogue | 快手盗贼、见习刺客、诡术学徒 |

这 15 名角色能先验证：

- `3 人主羁绊` 是否容易成型。
- 六维与阵营标签是否能在 8 人部署上限内重叠。
- 酒馆招募卡是否能显示角色补齐的羁绊。
- 羁绊栏是否能按主羁绊、小羁绊、层数和激活状态正确排序。

## 七、后续延申规则

1. **稀有角色从基础角色升级而来**  
   高稀有角色可以保留同职业与小分支，但拥有更鲜明的技能。例如“冠军剑士”可以延申为擅长破甲的冠军将领；“防护法师”可以延申为专门保护后排的结界大师。

2. **延申优先改变技能细节，不轻易改变标签**  
   标签是构筑稳定性的基础。除非角色定位发生明显变化，否则同一小分支的延申角色应尽量保留原有职业、主属性和主要阵营。

3. **双职业角色作为高稀有度例外**  
   例如“奥法骑士”未来可以延申出战士/法师双职业角色，同时贡献两个主羁绊，但应提高部署成本或酒馆等级要求。

4. **小分支专属遗物优先绑定基础模板**  
   遗物可以强化某一小分支的基础技能。例如“学识手册”强化学识歌者的鼓舞，“铸甲工具箱”强化铸甲学徒的护盾。

5. **基础技能不要承担终局构筑全部乐趣**  
   角色基础技能负责识别定位；真正改变战斗节奏的部分应来自职业主羁绊、遗物、事件和高稀有延申角色。
